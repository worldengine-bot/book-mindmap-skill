# Prompt 工程参考文档

> 本文档说明 book-to-mindmap 使用的 Prompt 设计原理与自定义方法。

---

## 架构概览

整个 pipeline 中 LLM 被调用两类任务：

| 调用 | 目的 | 输入量 | 模型 |
|------|------|--------|------|
| **结构识别** | 判断书名、流派、章节划分 | ~12 000 字（前部取样） | deepseek-chat |
| **逐章摘要** | 每章的结构化提炼 | ~8 000-15 000 字（单章） | deepseek-chat |

两者均要求 **严格 JSON 输出**，通过 `response_format: json_object` 强制约束。

---

## 流派模板

`summarize_chapters.py` 内置 6 种流派的分析指令，会根据书籍类型自动注入章节摘要 Prompt：

### business（商业/管理）
```
1. 作者的核心主张与底层商业逻辑
2. 支撑数据、研究引用或企业案例
3. 可执行的策略框架与行动建议
4. 反直觉的洞见或挑战常识的观点
```

### philosophy（哲学/思想）
```
1. 核心哲学命题与论证路径（前提→推论→结论）
2. 与其他思想流派/思想家的对话或批评
3. 关键概念的界定与精细区分
4. 论证的实践意涵与可能的局限性
```

### tech（技术/工程）
```
1. 核心技术概念、原理与设计哲学
2. 适用场景、设计权衡与限制条件
3. 与其他技术的对比（替代/互补/依赖）
4. 常见误区、最佳实践与发展趋势
```

### literature（文学/叙事）
```
1. 情节推进、叙事手法与结构设计
2. 人物发展、关系演变与心理变化
3. 核心意象、象征与主题深化
4. 语言风格、情感张力与审美特征
```

### academic（学术/研究）
```
1. 研究问题、理论框架与核心假设
2. 方法论选择、数据来源与因果推断
3. 核心发现与对已有文献的贡献
4. 研究局限与未来可探索的方向
```

### self-help（自我提升）
```
1. 核心理念与需要改变的心智模式
2. 具体方法与可操作步骤
3. 背后的心理学/神经科学/行为经济学依据
4. 常见的执行障碍与突破策略
```

## 详细程度对比

| 字段 | summary | standard | detailed | comprehensive |
|------|---------|----------|----------|---------------|
| 核心论点 | ≤3 | ≤4 | ≤5 | ≤6 |
| 概念定义 | ≤20 字 | ≤30 字 | ≤40 字 | ≤50 字 |
| 论据/证据 | — | 有 | 含强度评估 | 含来源+反面证据 |
| 案例 | — | ≤2 | ≤3（含细节） | ≤4（完整保留） |
| 引文 | — | — | 有 | 含上下文+重要性 |
| 论证结构 | — | — | — | 有（premises→conclusion） |
| 跨章联系 | — | — | 有 | 有 |
| 批判性评述 | — | — | 可选 | 详细 |
| 延伸阅读 | — | — | — | 有 |
| 每章 token | ~2k | ~4k | ~6k | ~8k |
| 适用场景 | 超大书快速概览 | 常规阅读笔记 | 深度学习（推荐） | 学术研究/写书评 |

## 自定义模板

如需针对特定类型书籍微调，编辑 `summarize_chapters.py` 中的 `GENRE_INSTRUCTIONS` 字典即可。
也可通过 `--genre auto` 让模型自动判断并选择最合适的分析角度。

### 添加新流派

```python
# 在 GENRE_INSTRUCTIONS 中添加
"history": (
    "请从历史分析角度提炼本章，重点提炼：\n"
    "1. 事件因果链与关键转折点\n"
    "2. 史料来源与视角分析\n"
    "..."
),
```

## JSON 解析容错

模型输出 JSON 可能附带以下噪声，`safe_json_parse()` 按顺序处理：

1. 去除 Markdown 代码块包裹（```json ... ```）
2. 修复尾部逗号（`,}` → `}`）
3. 截取第一个完整 `{...}` 对象
4. AI repair：将原始输出发回模型请求修复（兜底）

## DeepSeek 特定优化

- **System Prompt 位置**：DeepSeek Chat API 的 system prompt 作为 messages 数组第一条（role: system），不像 Anthropic 有单独的 system 参数
- **JSON Mode**：使用 `response_format: {"type": "json_object"}` 约束输出，大幅减少格式错误
- **Temperature**：结构识别用 0.2（更确定），章节摘要用 0.3（保留一定灵活性）
- **token 估算**：中文约 2 字符/token，英文约 4 字符/token。DeepSeek Chat 上下文窗口 ≥ 64K tokens，单章文本一般无需截断
